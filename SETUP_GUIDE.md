## 📊 Database Setup (Required)

You need to run the database schema in your Supabase project. Here's how:

### Option 1: Supabase Dashboard (Recommended)

1. **Open Supabase SQL Editor**
   - Go to https://supabase.com/dashboard/project/yrobckylfnvmkkpbygge/sql/new
   - Or navigate to: Project → SQL Editor → New Query

2. **Copy the Schema**
   - Open `supabase/schema.sql` in this project
   - Copy the entire contents (it's a long file - make sure you get everything!)

3. **Run the Schema**
   - Paste the schema into the SQL Editor
   - Click "Run" or press Cmd/Ctrl + Enter
   - Wait for confirmation (should take 5-10 seconds)

4. **Verify Setup**
   After running, you should see these tables in your database:
   - `users`
   - `interests` (with 35+ pre-populated interests)
   - `user_interests`
   - `subjects` (with Math, Science, Reading, History)
   - `topics`
   - `user_progress`
   - `session_logs`
   - `question_responses`
   - `generated_content`
   - `lessons`

### Option 2: Using Supabase CLI (Advanced)

If you have Supabase CLI installed:

```bash
supabase db push
```

## 🔍 Troubleshooting

### Error: "Missing Supabase environment variables"
- Check that `.env` exists in the root directory
- Verify the file has the correct variable names (starts with `VITE_`)
- Restart the dev server

### Error: "Failed to load interests"
- Make sure you ran the database schema in Supabase
- Check the Supabase SQL Editor for any errors
- Verify RLS policies are enabled (they're created by the schema)

### Error: "Failed to generate lesson"
- Verify your Gemini API key is correct
- Check Google AI Studio for API quota/limits
- Look at browser console for specific error messages

### Questions Not Loading in Diagnostic Quiz
- This is expected if Gemini API fails
- The quiz will skip to completion
- You can still continue to the Dashboard

## 📋 Verify Database Setup

Run this query in Supabase SQL Editor to check if seed data loaded:

```sql
-- Check interests (should return 35+)
SELECT COUNT(*) as interest_count FROM interests;

-- Check subjects (should return 4)
SELECT * FROM subjects;

-- Check if RLS is enabled (should return 't' for all)
SELECT tablename, rowsecurity
FROM pg_tables
WHERE schemaname = 'public'
AND tablename IN ('users', 'user_interests', 'user_progress');
```

Expected results:
- Interests: 35+ rows
- Subjects: 4 rows (Math, Science, Reading, History)
- RLS: All tables should show `true`
